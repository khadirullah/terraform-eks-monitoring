# Run 1, 2026-10-28

The first time this repo was applied to a real cluster. Before that it had only
passed `terraform validate`.

Logs:

- [logs/run-1/terminal-output.txt](logs/run-1/terminal-output.txt). Notes from the
  run, with the real output under each command.
- [logs/run-1/key-lines.txt](logs/run-1/key-lines.txt). Key lines from my
  terminal, such as apply timings and the DNS error.

## What I did

1. Ran `scripts/deploy.sh`. Terraform created 28 resources in about 13 minutes.
   The control plane alone took 10 minutes 15 seconds.
2. Checked that all ten Prometheus scrape targets were up.
3. Started a pod that exits straight away, to test `PodCrashLooping`.
4. Stopped the kubelet on one node, to test `NodeNotReady`.
5. Rebooted that node to bring it back, then ran `scripts/destroy.sh`.

## What I saw

- **The deploy stopped at its first kubectl call.** My VM's DNS resolver
  answered "no such host" for the new cluster endpoint and cached that answer
  for a few minutes. A line in `/etc/hosts` got past it. The runbook now
  explains this gap.
- **Both alerts fired and reached Alertmanager.**
- **`PodCrashLooping` went quiet while the pod was still broken.** It fired,
  then went back to inactive ten and a half minutes later, with the pod still
  in CrashLoopBackOff. The rule counted restarts in 15 minutes, and once the
  back-off reached 5 minutes too few restarts fit in that window.
- **Grafana restarted on its own.** Its liveness probe timed out and the
  kubelet killed the container. The 512Mi memory limit was too small.
- **The destroy plan showed `upgrade_policy` set to `EXTENDED`.** The repo never
  set it, so AWS used its default. Once the version leaves standard support, an
  `EXTENDED` cluster bills at the extended rate.
- **The README listed Grafana dashboards that nothing provisions.**
- **The node test.** The node went `NotReady`, Kubernetes added its taints, and
  after 5 minutes the Deployment pods on it, Grafana and Alertmanager, were
  replaced on the other node. They did not move back after the reboot.
  node-exporter is a DaemonSet pod, so it stayed on the stopped node.
- **The destroy took 478 seconds.** All 28 resources were destroyed, and a
  separate AWS CLI check found nothing left.

## What changed after it

- `PodCrashLooping` alerts on the CrashLoopBackOff state itself, smoothed over
  the restart gaps.
- Grafana has a 1Gi limit, a 384Mi request and a 5 second probe timeout.
- The cluster sets `upgrade_policy { support_type = "STANDARD" }`.
- The README no longer promises dashboards.
- The runbook covers the DNS gap, both failure tests and the kubeconfig cleanup.
